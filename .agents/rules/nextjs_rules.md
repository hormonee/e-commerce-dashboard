# 🚀 Next.js App Router 개발 가이드라인 (Rules)

본 문서는 이커머스 대시보드 프로젝트에서 Next.js(App Router)를 활용할 때 팀원 전원과 AI가 **반드시 준수해야 하는 핵심 컨벤션 및 개발 규칙**을 정의합니다.

이 규칙은 이전에 작성한 `architecture.md`의 클린 아키텍처 원칙과 결합하여, 유지보수가 쉽고 안정적이며 성능이 뛰어난 코드를 작성하는 것을 목표로 합니다.

---

## 1. 렌더링 최적화 및 컴포넌트 설계

### 1-1. 서버 컴포넌트(Server Component) 우선 원칙
- 모든 컴포넌트는 **기본적으로 서버 컴포넌트(RSC)**로 작성합니다.
- `useState`, `useEffect`와 같은 React 훅, 브라우저 전용 API(`window`, `document`), 혹은 이벤트 리스너(`onClick` 등)가 절대적으로 필요한 경우에만 예외적으로 클라이언트 컴포넌트를 사용합니다.

### 1-2. 클라이언트 경계 최소화 (Push Down 'use client')
- `'use client'` 지시어는 페이지 트리의 최대한 아래쪽(Leaf Node)으로 밀어내어 선언합니다.
- 페이지(`/app/.../page.tsx`) 전체나 대규모 레이아웃 컴포넌트를 클라이언트 컴포넌트로 만들지 않습니다.
- 인터랙션이 필요한 작은 UI 덩어리(예: 드롭다운 토글, 찜하기 버튼)만 클라이언트 컴포넌트로 분리합니다.

### 1-3. 파일 모듈화 (단일 책임 원칙)
- **한 파일의 크기가 너무 커지거나 복잡해지면(권장 기준: 150~200줄 이상) 반드시 여러 파일로 분할합니다.**
- UI 조각들은 `components/` 폴더 하위로, 데이터 가공 및 비즈니스 로직은 `hooks/`(Client) 또는 `use-case/`(Server)로 분리하여 코드의 가독성을 높입니다.

---

## 2. 상태(State) 및 데이터 관리

### 2-1. URL을 통한 상태 공유 (URL as State)
- 검색어(Search), 필터링 옵션(Filter), 페이지네이션(Pagination) 등 다른 사용자와 공유가 가능해야 하는 상태는 `useState` 대신 URL의 **`searchParams`** (또는 `useSearchParams()`)를 활용합니다.
- 이를 통해 서버 사이드 렌더링 시에도 URL만으로도 올바른 초기 데이터를 그려낼 수 있습니다.

### 2-2. 데이터 패칭은 서버에서 (Fetch Data on the Server)
- 외부 API 호출이나 데이터베이스 통신(Infrastructure 계층 통신)은 가급적 **서버 컴포넌트(Server Component)** 내에서 수행합니다.
- 데이터를 불러온 뒤, 자식 클라이언트 컴포넌트에는 프롭스(Props)를 통해 **직렬화 가능한 순수 데이터(Plain JSON Object)**만 전달합니다.

---

## 3. 데이터 변경 (Mutation) 패턴

### 3-1. Server Actions의 적극적 활용
- 단순 폼(`form`) 전송이나 데이터의 생성(Create)/수정(Update)/삭제(Delete) 로직은 `app/api/...`에 별도의 Route Handlers를 만들기보다는 **Next.js Server Actions**을 선언적으로 활용합니다.
- 이를 통해 클라이언트와 서버 간의 컨텍스트 스위칭 코드를 줄이고 직관적인 흐름을 유지합니다.
- 서버 액션 내에서도 비즈니스 로직은 직접 구현하지 않고, Application 계층의 **UseCase**를 호출하여 처리합니다.

---

## 4. 간결하고 안전한 코드 작성 (Best Practices)

### 4-1. 조기 반환(Early Return) 패턴 생활화
- 중첩된 `if-else` 블록은 가독성을 크게 떨어뜨립니다.
- 조건에 부합하지 않거나 에러 상태일 경우 즉시 코드를 종료하고 반환(Early Return)하여, 메인 로직의 들여쓰기(Depth)를 최소화합니다.

### 4-2. 구체적이고 명시적인 에러 핸들링
- 범용적인 `error.tsx`나 브라우저 전역 에러 바운더리에만 의존하지 마십시오.
- 폼 전송 액션이나 데이터 패칭 시 실패가 예상되는 지점에는, 도메인 에러(예: `ProductNotFoundError`)를 캐치하여 사용자에게 정확한 Toast 메시지나 경고 UI를 노출하도록 세밀하게 핸들링합니다.

### 4-3. 성능 최적화를 위한 내장 컴포넌트 사용
- 정적 자원(이미지, 링크)을 다룰 때는 일반 HTML 태그(`<img>`, `<a>`) 대신 **Next.js가 제공하는 내장 최적화 컴포넌트(`next/image`, `next/link`)를 반드시 사용**합니다. (이미지 자동 리사이징 및 화면 밖 이미지 레이지-로딩, 페이지 프리패칭 이점 활용)
